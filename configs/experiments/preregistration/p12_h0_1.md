# Pre-registration: H0.1 (spec §51 Phase 12, §6, §38.5)

**Status:** drafted alongside Phase 12's implementation, evaluated on **validation-split worlds only**. Spec's §38.5 commit-and-hash gate ("before any test-split evaluation") does not fire for this run -- H0.1 itself is defined against val worlds, not test worlds -- but the draft is recorded now regardless, as spec's own Phase 12 task item asks for, so RQ1's real test-split evaluation (a later phase, tagged against H1 in the hypothesis table) has this document as its starting point rather than a blank one.

## Hypothesis

| ID | H0 (null) | H1 (alternative) | Primary metric | Min. meaningful effect |
|---|---|---|---|---|
| H0.1 (sanity) | Frontier <= random | Frontier > random coverage | C(180s) | +10 pp |

This is explicitly a **sanity check**, not RQ1 itself: it establishes that the classical frontier baseline is doing something non-trivial before any learned method is compared against it. A failure here is a baseline-bug signal (spec's own line), not a scientific finding.

## Metrics

- **Primary:** `C(180s)` -- coverage at t=180s of simulated flight, per spec §41: `C(t) = |E_GT(t) ∩ F| / |F|`, computed by the evaluator via GT-pose raycasting against exact `WorldSpec` geometry (`aeris.evaluation.metrics.coverage`), independent of either method's own (possibly imperfect) map.
- **Secondary (descriptive only, not part of the H0.1 decision rule):** `T_c(0.5)`, `T_c(0.8)` (time-to-coverage-threshold, censored at T_max=180s); planner latency p50/p95 (validation gate item, not H0.1 itself); shield intervention rate; `n_subgoals_chosen`/`n_rotate_scans` (diagnostic, not a reported research metric).

## Statistical test

Paired bootstrap CI on the difference `mean(C_frontier) - mean(C_random)`, paired by `(world, run_index)` (spec §6's "evaluation is paired: every method runs on the same (world seed, start pose) pairs"), 10,000 resamples, alpha=0.05 (`aeris.evaluation.statistics.paired_bootstrap_ci`, already built and unit-tested in Phase 7). H0.1 is **rejected in favor of H1** iff the CI excludes 0 **and** the point estimate exceeds +10 percentage points (spec §6's "meaningful" definition, applied literally).

No Holm-Bonferroni correction is needed for H0.1 alone (a single comparison); it will apply once RQ1's full comparison set (frontier / utility-frontier / learned, pairwise) is evaluated on test worlds in a later phase.

## Worlds, seeds, episodes

- **Split:** `val` (seed range [10000, 10200), ADR-010) -- generated fresh for this phase via `aeris.simulation.worlds.batch.generate_batch`, **not** the 5 `test_id`-tagged obstacle-suite worlds Phases 9-11 reused (confirmed via `aeris/simulation/worlds/obstacle_suites.py`'s own `_TAG_SPLIT = WorldSplit.TEST_ID`) -- those are the wrong split for a validation-worlds requirement, and reusing them here would have been a real split-discipline violation, not just an inconsistency.
- **Worlds:** 3 val-split worlds, one from each of the 3 available procedural families (`f1_rubble`, `f2_office`, `f3_warehouse`; `f4_collapsed` is pinned to `test_ood` only per spec and is never generated as `val`), seed 10000 within each family. Scoped down from a larger "many worlds per family" ideal for the same honestly-documented time-budget reason every prior phase's experiment was (Phase 9: 8/family not 50; Phase 10: 5 runs not 10) -- one real live PX4+Gazebo episode per (world, method, repeat) triple, at up to ~200s each, makes a much larger grid impractical on this Mac within the phase's time budget.
- **Methods:** `random`, `nearest_frontier`, `utility_frontier`.
- **Repeats per (world, method) pair:** 3 (spec §6's own stated minimum for classical methods in SITL).
- **Total episodes:** 3 worlds x 3 methods x 3 repeats = 27.
- **T_max:** 180.0s (matches C(180s) exactly; no need to run longer since H0.1 doesn't ask for T_c(x) as its own decision metric).

## Exclusion rules

An episode that fails to launch (the documented, pre-existing PX4/EKF boot flakiness -- spec §43, recurring since Phase 3) is retried once (`_MAX_LAUNCH_ATTEMPTS = 3`, matching Phase 9-11's own retry pattern) and recorded as `invalid` with its cause if all attempts fail, never silently dropped (spec §38.4). No other exclusion rule applies -- every episode that completes any real flight time contributes its recorded coverage trace, including one that never reaches the full 180s (its last recorded C(t) is used, matching a censored `T_c(x)`).

## Checkpoint-selection rule

Not applicable this phase -- no learned checkpoint exists yet (that's Phase 19, per H1's own phase tag). Utility-frontier's own tunable parameter (`lambda_turn`) is selected via a small grid search on validation worlds *before* this comparison run, with that budget recorded separately in the phase report (spec's own "tuning budget... documented alongside the learned policy's hyperparameter budget" line) -- not a checkpoint in spec's §38.5 sense, but the same spirit: chosen on validation data only, before any test-split evaluation exists to leak into.
