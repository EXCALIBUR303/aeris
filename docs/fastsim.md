# FastSim (Tier F) and the RL environments

Phase 13 (spec §51) builds the training simulator the RL track runs on, and
the parity evidence that says how far its results can be trusted on Tier H
(PX4 SITL + Gazebo). Every number below comes from a committed artifact
under `results/` or `configs/fastsim/`, regenerated by the script named next
to it.

## Architecture

```
WorldSpec ──build_world──▶ FastWorld (uint8 voxels, 0.1 m) ──▶ WorldBank [W,NX,NY,NZ]
                                                                     │
FastSimBatch (N envs) ── BatchDynamics (identified, dt_sim 0.02 s) ──┤
                     ── cast_rays_batch (Numba DDA, parallel) ───────┤
                     ── shield_batch (Numba port of S3, bit-identical)
                     ── pose estimate = truth + random walk + white noise
        │
        ├── LocalNavCore ─▶ LocalNavEnv (gym.Env) / LocalNavVectorEnv (SAME_STEP autoreset)
        ├── ExplorationEnv (decision-level, 25 masked actions, ADR-0015)
        └── FastSimVehicle (VehicleInterface + CommandPort, N=1)
```

| Module | What it is |
|---|---|
| `aeris/simulation/fastsim/world.py` | `build_world()` voxelizes a `WorldSpec` with the same center-in-primitive rule as Phase 9's `voxelize()` (tested equal); `WorldBank` zero-pads worlds into one array so a batch can mix worlds. |
| `sensors.py` | Amanatides–Woo DDA through the voxel grid plus an analytic ground plane; `camera_ray_dirs()` from the real `front_depth` intrinsics (`configs/vehicle/sensors.yaml`), strided; ranges converted to z-depth. Tested against a brute-force marcher. |
| `dynamics.py` | Per-axis first-order lag + integer delay (ring buffer) + acceleration clip, explicit Euler at 0.02 s, for vx, vy (shared params) and yaw rate. Altitude is held. |
| `sysid.py` | The fitter: grid search + local refinement over (τ, delay, a_max) on step windows, a Numba cost that is literally the same discretization as `BatchDynamics`, bootstrap CIs by multiplicity weights. |
| `shield.py` | Numba port of `aeris.safety.shield` (sector memory, FOV mask, braking-distance clamp); `test_fastsim_shield_parity.py` checks it bit-for-bit against the Python original. |
| `batch.py` | `FastSimBatch`: camera rig, pose-noise model, collision (sphere r_v = 0.3 m vs voxels), geodesic field (Dijkstra, reward only). |
| `agent_map.py` | The exploration agent's own 2D log-odds map, integrated from rendered depth at the *estimated* pose. |
| `vehicle.py` | `FastSimVehicle`: Tier H's command semantics (setpoints consumed only in OFFBOARD, HOLD, LAND at 0.7 m/s, odom origin = arm point, no disarm in air). Vertical motion is a plain lag, not identified. |
| `aeris/learning/spaces/` | Observation specs + builders + action decoders shared with deployment (spec §27.6). Import-linter forbids this package from importing any simulator or env. |
| `aeris/learning/envs/` | `local_nav.py`, `exploration.py`, `rewards.py` (v1, §27.5), `wrappers.py` (runtime observation contract). |

## System identification (gate 1)

`scripts/sysid/record_tier_h.py --session steps` flies velocity steps live in
Tier H at 2 m: x/y amplitudes 0.5/1.0/1.5/2.0 m/s, yaw 0.3/0.6/0.9 rad/s, each
held 2.5 s then 2 s rest, all twice. Repetition 0 trains, repetition 1 is
held out. `scripts/sysid/fit_dynamics.py` writes `configs/fastsim/dynamics.yaml`.

| Axis | τ (s) [95% CI] | delay (s) [CI] | a_max [CI] | train RMSE | **held-out RMSE** |
|---|---|---|---|---|---|
| vx | 0.44 [0.40, 0.49] | 0.28 [0.24, 0.30] | 3.4 [2.4, 4.2] m/s² | 0.079 | 0.062 m/s |
| vy | 0.41 [0.40, 0.42] | 0.30 [0.26, 0.30] | 4.5 [2.6, 4.5] m/s² | 0.056 | 0.056 m/s |
| **xy pooled (used)** | 0.44 [0.41, 0.45] | 0.28 [0.26, 0.30] | 4.0 [2.9, 4.6] m/s² | 0.069 | **0.059 m/s** |
| yaw | 0.23 [0.20, 0.24] | 0.12 [0.10, 0.14] | 2.5 [1.6, 2.7] rad/s² | 0.021 | **0.024 rad/s** |

Gate ≤ 0.15 m/s: **pass** with 2.5× margin. The delay grid was widened to
0.5 s after a first fit landed on its 0.30 s edge; the optimum stayed at an
interior 0.28 s. FastSim uses one shared horizontal model, so vx and vy are
fit both separately and pooled. The pooled fit is the one used and scored;
the per-axis fits stay in the YAML so the vx/vy accel asymmetry is visible.

## Pose-error model and open-loop parity (gate 2)

`record_tier_h.py --session openloop` flies 10 seeded, mirrored 20 s velocity
sequences while logging both the GT model pose and PX4's EKF estimate.

- **Pose noise** (`scripts/sysid/analyze_openloop.py` →
  `configs/fastsim/pose_noise.yaml`): from samples with speed < 0.3 m/s and
  |yaw rate| < 0.1 rad/s, so command timing doesn't masquerade as error. White
  noise σ = 1.94 cm, random-walk step 0.81 mm per 0.1 s, yaw σ = 0.030 rad.
- **Trajectory parity** (`results/sysid/parity_trajectory.json`): FastSim
  replays each recorded command sequence from the recorded start state.
  Position RMSE is 0.118 to 0.206 m (mean 0.160 m), and the worst final error
  is 0.33 m. Gate ≤ 0.5 m for every sequence: **pass**.

## Depth parity (gate 3)

`scripts/sysid/depth_parity.py` hovers at 1 m in `f2_office_10000`, captures
8 yaws (4 s settle each), and renders the same poses in FastSim.

**The 0.24 m finding.** The first comparison had ground-plane depths ~30% off.
Gazebo's model pose for `x500_base` sits 0.24 m *below* `base_link`
(`<pose>0 0 .24 ...` in its model.sdf), and `sensors.yaml` extrinsics are
relative to `base_link`. `GZ_MODEL_TO_BASE_LINK_M` in `batch.py` now
encodes that offset. Anything that composed a GT model pose directly with
sensor extrinsics, like Phase 11's GT-pose map condition, inherited a 0.24 m
vertical error. See "Implications for earlier phases".

| Voxel resolution | Pooled median \|Δd\|/d | Worst single frame |
|---|---|---|
| 0.1 m (training default) | **1.5%** | 5.96% |
| 0.05 m | 1.5% | 6.5% |
| 0.025 m | 0.10% | 0.41% |

The spec's wording, "median absolute depth error ≤ 5% on matched frames", is
met on the pooled median at every resolution. A stricter reading (every frame
≤ 5%) fails at 0.1 m because of one near-wall frame. The 0.025 m row shows
the residual is voxel quantization: a 0.1 m grid places a wall face up to
0.05 m from its true plane, depending on how the wall falls relative to the
grid. Near a wall that is a large relative error, and halving the voxel size
doesn't help when the wall still falls badly. An earlier draft of this
analysis read the 0.05 m row as "not quantization"; the 0.025 m run
corrected that. Training stays at 0.1 m for throughput, and this is a known
fidelity cost close to walls.

## Exploration parity (gate 6)

`scripts/fastsim/parity_exploration.py` runs Phase 12's own `NearestFrontierExploration`
(the gate) and `RandomExploration` (context) through `ExplorationEnv.execute_subgoal`.
It uses Phase 12's three val worlds and spawns, 3 seeds each, and scores C(180)
with Phase 12's evaluator at 0.5 m. Tier H numbers come from Phase 12's
`runs.jsonl` (3 runs per world/method). The spec gives no numeric threshold
for this gate ("within a reported gap"), so none was invented after the fact.

**Nominal** (10 Hz, fixed heading: the faithful mirror of Phase 12's loop):

| World | FastSim NF (range) | Tier H NF (range) | Gap | Shield, FastSim / Tier H |
|---|---|---|---|---|
| f1_rubble | 0.146 (0.145–0.146) | 0.157 (0.146–0.172) | **−0.011** | 0.99 / 0.85 |
| f2_office | 0.667 (0.244–0.880) | 0.900 (0.873–0.954) | **−0.233** | 0.96 / 0.92 |
| f3_warehouse | 0.213 (0.213–0.213) | 0.203 (0.191–0.213) | **+0.009** | 0.99 / 0.93 |

**Office has no valid Tier H reference.** A retroactive audit of Phase 12's
ULogs (`scripts/audit_p12_ulog_altitude.py`, commit a1514c1, see
`docs/exploration.md`) finds **all three** office nearest-frontier episodes
invalid: GT altitude below the band for 3.3–13.6 s right after the takeoff
handover. Every audited rubble and warehouse episode is valid. Against valid
references only, the gaps are **−0.011 (rubble) and +0.009 (warehouse), mean
|gap| 0.010**, both inside Tier H's own run-to-run range. Including office
anyway, mean |gap| is 0.084. Office is still informative about FastSim: two
seeds land at 0.877 and 0.880, and the third deadlocks (below). The
`tierh_rate` condition (0.5 s control period, matching Tier H's measured
loop) gives the same picture: −0.008 / −0.238 / +0.009.

**What both tiers are actually doing.** In rubble and warehouse, neither tier
explores. The shield's sector memory is body-frame and only the ±36.5° FOV
sectors are ever updated, so out-of-FOV sectors sit at 0 m forever. Frontier
paths usually leave at 45° diagonals, outside that cone, so the command is
clamped to zero. Instrumented Tier H runs (`scripts/fastsim/trace_tierh_exploration.py`)
show it directly. The rubble vehicle's maximum displacement from spawn was 0.23 m
over 180 s, and warehouse's 0.18 m. FastSim's nearest-frontier vehicle travelled
0.0–0.04 m. Coverage in this regime is set by *where the camera ends up
pointing*: one startup rotate scan, plus any later scans.

**Why FastSim deadlocks harder in office.** Tier H's 3D voxel map, projected
to the band, flickers by ≥ 20 inflated cells per tick even when stationary
(EKF jitter in 3D), so Tier H replans every ~0.9 s (median) and its nearest
frontier keeps changing. Sooner or later a target lands inside the FOV.
FastSim's 2D map is stable when stationary (it does flicker in rubble), so a
stalled decision repeats for its full 45 s timeout with the same target. The
gap is real fidelity, not noise. FastSim lacks Tier H's mapping jitter. It is
reported rather than tuned away by injecting artificial flicker.

**Random is where parity is weakest:** rubble FastSim 0.711 vs Tier H 0.371 (Tier H
range 0.206–0.512). Random's rotate option fires far more often in FastSim
(22–32 scans per episode). FastSim reproduces the *direction* of Phase 12's H0.1
reversal (frontier − random = −0.264, 95% CI [−0.457, −0.073]; Tier H −0.072
[−0.164, +0.009]) but exaggerates it.

**The Phase 12 hypothesis, tested (`face_travel`: yaw toward the travel direction).**

| World | NF C(180), nominal → face_travel | NF shield rate |
|---|---|---|
| f1_rubble | 0.146 → **0.623** | 0.99 → 0.05 |
| f2_office | 0.667 → **0.951** | 0.96 → 0.17 |
| f3_warehouse | 0.213 → **0.542** | 0.99 → 0.06 |

Frontier − random goes from −0.264 [−0.457, −0.073] to −0.034 [−0.152, +0.092]:
the reversal disappears. In FastSim, Phase 12's heavy shield throttling and
its H0.1 result trace to flying with a fixed heading behind a forward-only
shield, not to the frontier strategy. This is a FastSim result. Tier H has no
`face_travel` run yet, so it predicts what a Tier H re-run should show rather
than proving it. Even with face_travel, nearest-frontier travel stays short
in rubble (1.0–1.8 m; ~80 rotate scans per episode). Near clutter the
vehicle's own cell becomes inflated-occupied, A* refuses to start, and the
fallback scan holds position, a dead end the classical loop has in both tiers.

**Instrumented Tier H re-runs.** Warehouse C = 0.207, valid and in line
with Phase 12. Rubble scored C = 0.488 (Phase 12: 0.146–0.172), but it lost
altitude for ~10 s while PX4's EKF believed it was flying, which makes it invalid
under the GT-altitude rule; it's used only as mechanism evidence (replan
cadence, deadlock), never as coverage data. A third, office run never climbed
at all: every A* failed, and Phase 12's loop corrects altitude only through
path following, so it spun on the floor and scored C = 0.985. It's excluded
(`results/fastsim/tierh_trace/*/{INVALID,ANOMALY}.md`). Tier H exploration
coverage could therefore include grounded time the evaluator couldn't see.
That defect is in the Phase 12 harness, not FastSim. It was fixed in a
separate commit (a1514c1: explicit altitude hold on every command plus a GT-altitude
validity check; the rubble drop was diagnosed as EKF2 vertical-velocity
divergence after an IMU-sample dropout).

## The environments

**Local navigation** (`LocalNavEnv`, `LocalNavVectorEnv`): observation is
`depth` (1×30×40, normalized z-depth, stride 16 from 640×480) plus `state`(10)
(body-frame goal vector and distance, body velocity, previous action, all from
the pose *estimate*). Action is a 3-vector in [-1, 1] decoded to body-frame
(vx, vy, yaw rate). The decoder slew-limits to 1.8 m/s² so consecutive
setpoints never trip the S1 validator's 2.0 m/s² check. The 10 Hz control
step runs 5 dynamics substeps, and the shield sits between decoder and
dynamics, as on the vehicle. `terminated` means collision or success;
`truncated` means time limit or out of bounds. Split discipline: `train` mode
refuses non-train worlds, `val` mode refuses test worlds.

**Exploration** (`ExplorationEnv`): one step is one *decision*. There are 25
masked egocentric actions (12 bearings × 2 ranges + rotate, ADR-0015), and the
observation is an 8×64×64 two-scale egocentric map crop plus a 3-vector state.
Execution mirrors Phase 12's `run_exploration_episode`: A* on the inflated
agent map, waypoint following, the shield, a 2 s rotate at 0.6 rad/s,
replanning on a 20-cell map change, a 45 s per-decision timeout and a ±8 m
map window. The agent map is integrated from rendered depth at the estimated
pose. Fallbacks match Tier H's: an A* failure or a masked action becomes the
rotate scan (flagged `failed`). A* starts from the raw cell under the pose,
in both execution and the action mask, so an unmasked action is always
plannable. Every decision spends at least one control tick, so no policy can
freeze the episode clock.

**Randomization** (`configs/fastsim/randomization.yaml`, loaded by
`LocalNavEnvConfig.identified()`): per-episode τ ×[0.8, 1.25], delay
+[-0.04, +0.06] s, a_max ×[0.6, 1.2], depth noise [0, 1%]. Each range is
derived in the YAML's comments from the sysid CIs. `randomization: None` is
the A5/H4 "off" arm.

## Implications for earlier phases

1. **Phase 12's shield throttling and H0.1 reversal.** The shield's
   body-frame memory only updates the ±36.5° FOV sectors, and Phase 12's
   exploration loop never yaws toward its direction of travel. Any leg more
   than ~40° off the nose is clamped to zero. In FastSim, yawing toward
   travel cuts the shield rate from 0.99 to 0.05 and removes the reversal
   (gate 6). A Tier H re-run with that change is the confirming experiment.
2. **Phase 11's pose-error attribution.** Measured stationary GT-vs-EKF error is
   ~1.9 cm, far below the 0.13–0.17 m `eph` PX4 self-reports, which Phase 11
   used as its pose-error scale. That weakens Phase 11's attribution of map
   error to pose error, at least for translation (rotation wasn't measured
   here).
3. **GT model pose vs base_link (0.24 m).** See depth parity. Phase 11's
   GT-condition map composed the GT model pose with extrinsics and so placed
   the camera 0.24 m low.
4. **Tier H loop rate.** Phase 12's exploration loop effectively ran at
   ~0.5 s per tick (its synchronous GT-pose poll), not 10 Hz. Gate 6's
   `tierh_rate` condition reproduces that.
5. **Tier H altitude failures in exploration episodes** (gate 6 section):
   Phase 12's loop has no explicit altitude hold, and grounded time is
   scored as coverage.
6. **Coverage evaluator performance.** `point_in_box` rebuilt each box's
   inverse transform per call, so scoring one 180 s episode took ~30 min.
   Phase 13 memoizes the inverse and adds an exact bounding-sphere early-out.
   Output is bit-identical (`test_point_in_box_fast_path_matches_reference_rotation_test`)
   and ~15× faster.

## Known limitations

- Vertical dynamics aren't identified; every FastSim task holds altitude.
- The exploration agent map uses per-column log-odds, an approximation of
  Phase 11's 3D voxel map + band projection.
- Depth fidelity near walls is limited by 0.1 m voxels (see gate 3).
- Depth-noise randomization is batch-wide (one draw shared across a vector
  env), resampled on each reset.
- The pose-noise model is fit from near-stationary samples; error growth
  during aggressive rotation isn't modeled.
